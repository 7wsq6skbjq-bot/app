# RCA — Redeploy failed at build_image (ECR repository full)

**Deployment:** dev-retrieval (af33bb18-e3a2-41d6-9599-07fd584baa93)
**Failed run:** 773e1b66-8c7f-4438-9c9b-c817e3dbd93e (type: redeploy)
**Failed step:** build_image (push phase, Cloud Build step #51)
**Live app:** UNAFFECTED — active run 04941c8e still serving https://dev-retrieval.emergent.host

## Root Cause
The container image built successfully but could NOT be pushed. AWS ECR denied the push:

```
ERROR: failed to push 287883095218.dkr.ecr.us-west-2.amazonaws.com/customers-app:773e1b66-8c7f-4438-9c9b-c817e3dbd93e:
denied: The repository with name 'customers-app' in registry with id '287883095218'
already has the maximum allowed number of images which is '500000'
(type: TerminalCloudBuildFailure, retryable: false)
```

The shared ECR repository `customers-app` in registry `287883095218` (us-west-2) has reached the hard AWS limit of 500,000 images. Every tenant image tagged by run_id pushes here, and the repo is now full.

## Why this is NOT fixable by the deployer agent
- Build compilation succeeded; failure is purely at the registry push boundary.
- Not a source-code, manifest, secret, or tier issue — no file edit changes ECR capacity.
- Marked `retryable: false` / `TerminalCloudBuildFailure`. Re-firing the pipeline will fail identically until the registry is remediated.

## Required Fix (Platform / Infra)
Emergent platform/infra team must reclaim ECR capacity on `287883095218.dkr.ecr.us-west-2.amazonaws.com/customers-app`:
- Prune/expire old/untagged images (lifecycle policy), or
- Raise the per-repository image quota (AWS service quota request), or
- Shard image tags across additional repositories.

After the registry has free capacity, redeploy run can be re-triggered.

## Impact
None to the running app. The previous successful image remains active and serving. Only new redeploys of apps pushing to this repository are blocked.
