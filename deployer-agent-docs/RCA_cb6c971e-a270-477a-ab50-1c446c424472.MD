# RCA — Portech ERP "missing" August/September expenses (dépenses)

## Verdict: NO DATA LOSS. Data is present in production; it is hidden by the month-filter default + the receipts being stored under unexpected months/years.

## Production DB confirmed
- db_name (production, read live): **`dev-retrieval-test_database`**
- Active run: `cb6c971e-a270-477a-ab50-1c446c424472` (live, serving traffic)
- Read-only `mongo_query`; nothing modified.

## 1. Total count in `erp_expenses`
**21 documents.** (Preview `test_database` had only 2 — expected; separate DB.)

## 2. Date-field integrity — null/empty/missing hypothesis is DISPROVEN
- `count({date: {$in: [null, ""]}})` = **0**.
- All 21 documents have a valid `YYYY-MM-DD` string in `date`. None are null, empty, or missing.
- Therefore the "invisible because date is null/empty" theory does NOT apply to this data. The invisibility is driven by the month VALUE, not a broken date field.

Key observations:
- **September fuel receipts DO exist**: four `Ultramar` @ $75 each (= $300) dated **2024-09-17** (Carburant). Plus one Sept 2026 doc: Canadian Tire $245.56 (Outils, not fuel).
- **No August documents in ANY year** (no 2024-08 / 2025-08 / 2026-08).
- **No 2025 documents at all.** Dates span 2020, 2024, 2026 only.
- The four Sept `2024-09-17` docs have `created_at` in **2026** (and ObjectId timestamps ≈ Oct 2026) — i.e. they were entered recently but the `date` was captured as 2024. The receipt `date` year does not match when the record was created, so the user-entered receipt dates appear to carry the wrong year.

## 4. GridFS receipt images
- `expense_receipts.files` = **9**
- `expense_receipts.chunks` = **113**
- Receipt images ARE present. Note: 19 of 21 docs carry a `receipt_filename` but GridFS holds only 9 files — a possible mismatch (some referenced images may not be stored in GridFS). Flagged for awareness; not the cause of the visibility issue.

## 5. Why the user sees them as "missing"
- `ExpensesPanel` defaults the month filter to the **current month** and has **no "all months" option**. The app is operating around **Oct 2026**, so the default view (month = 2026-10) shows only the two `2026-10` Ultramar docs. The list/summary endpoints filter `{date: {$gte:"YYYY-MM-01", $lt:"YYYY-MM-32"}}`, so every other month is excluded from view.
- The September fuel receipts sit under **September 2024**, not the current period — the user would have to manually navigate to 2024-09 to see them. The expected August receipts are not in the DB in any year.

## Fix
1. **Code (E1):** Give `ExpensesPanel` an "All months" / year-aware view (or make the list/summary return all when no `month` is supplied), so receipts dated in other months/years are reachable. This is the real remedy for the visibility complaint.
2. **User:** Verify the receipt `date` values. The Sept fuel receipts are stored as **2024-09-17** and there are **no August receipts** and **no 2025 records** at all — confirm whether these dates were entered with the wrong year (records were created in 2026). If dates are wrong, the user can correct them via the ERP edit UI.

## Reassurance for the user
Nothing was deleted. All 21 expense documents and their receipt images are intact in production `dev-retrieval-test_database`. The hundreds of dollars of fuel receipts (incl. the four $75 Ultramar Sept entries) are present — they are filtered out of the default current-month view, not lost.
